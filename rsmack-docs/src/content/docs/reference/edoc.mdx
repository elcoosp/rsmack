`edoc` is an attribute macro — generated by `megamac!(kind = Attr, name = edoc, doc = "readme")` — that evaluates `#[edoc((...))]` tuples of string literals, constant references, and const expressions into real `#[doc]` attributes. Crate path: `rsmack_edoc` (facade: `rsmack::edoc`, feature `edoc`).

## Signature

```rust
#[edoc(from = path::to::consts)]
#[edoc(("Element ", CONST, " expression ", 2 * 21))]
struct Item { ... }
```

## Item arguments

### from :badge[optional]{variant="note"}

- **Type:** `syn::Path`
- **Default:** none — without `from`, only item-level tuples are evaluated
- **Meaning:** module path that locates the constants file; `::` maps to `/` and `.rs` is appended relative to the calling crate's `src/` — `impls::sub::consts` reads `src/impls/sub/consts.rs`
- **Constraint:** `self` is not handled as a path segment
- **Example:** `from = consts`

### item-level tuple :badge[optional]{variant="note"}

- **Type:** a `syn::Expr` that must parse as a tuple
- **Meaning:** elements concatenated into the item's `#[doc]`; pre-existing docs on the item are overwritten
- **Placement:** a separate `#[edoc((...))]` attribute next to `#[edoc(from = ...)]`

## Applicable items

Only structs and enums carry field docs. Any other item is fatal: `Only structs and enums supported, other items cannot carry field docs`.

## Const-expression grammar

Elements are evaluated with a typed evaluator mirroring rustc's `min_const_eval` subset. Values keep machine types (`i128`, `f64`, `bool`, `char`, `Vec<u8>`, `String`) until doc assembly — there are no per-operation string round-trips.

| Kind | Supported forms |
| --- | --- |
| Literals | `&str`, integers (`i128` range), floats (`f64`), `bool`, `char`, byte strings |
| Unary | `-x`, `!x` (dereference `*` is unsupported) |
| Arithmetic | `+` `-` `*` `/` `%` (checked; div-by-zero and overflow reported) |
| Bitwise | `&` `\|` `^` |
| Shifts | `<<` `>>` (amount validated as `u32`) |
| Logic | `&&` `\|\|` |
| Comparison | `==` `!=` `<` `<=` `>` `>=` (same-kind operands; `bool` only `==`/`!=`) |
| Casts | `as i8..i128`, `u8..u128`, `isize`, `usize`, `f32`, `f64` — int narrowing wraps two's-complement (`300 as u8` → `44`), float-to-int saturates, `NaN` → `0` |
| Macros | `concat!` (renders non-strings too), `env!` (unset variable is an error), `option_env!` (defaults to empty string) |

Anything else reports `Unsupported const expression '...'` or `Unsupported const macro 'X!'` as a collected error.

## Constants-file resolution

1. The file is parsed as a real `syn::File`; a visitor walks `const` items through the module stack and keys each by full path (`nested::DEEP`).
2. Const-to-const references resolve lazily with per-key memoization; cycles report `Cyclic const dependency involving 'X'`.
3. A reference matches the exact full path first. A bare name falls back to a unique match; several candidates report `Ambiguous const 'NAME', qualify the path: 'a::NAME', 'b::NAME'`, no candidate reports `Unresolved const ident 'X'`.

## Caching

- Process-global cache keyed by file path, validated against `(mtime, len)`.
- N annotated items against one constants file cost one parse.
- Non-fatal issues stored with the cached file re-emit on every use.

## Error behavior

- **Fatal** (returned through `ExecEnv::finish_result`): unreadable constants file, unparsable constants file, unsupported item kinds.
- **Collected** (flushed together at the end): broken tuple payloads, unsupported expressions, unresolved/ambiguous constants. Every broken expression of an item reports in one pass; the failing element renders a `Missing:` placeholder in the doc while the rest still materialize.

## Example

```rust
use rsmack_edoc::edoc;

#[edoc(from = consts)]
#[edoc(("The ", APP, " client"))]
enum State {
    #[edoc(("Idle since ", TAG))]
    Idle,
    Busy,
}
```
