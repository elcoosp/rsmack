In this tutorial you install `rsmack`, document a struct's fields from constants with [`edoc`](/reference/edoc/), and wrap those fields in `Option` with [`wrap`](/reference/wrap/). You finish by reading the generated documentation in `cargo doc`.

## Prerequisites

- Rust **1.94 or newer**. Check with `rustc --version` and update with `rustup update stable` if needed.
- Familiarity with basic Rust: structs, modules, and `cargo` commands.

## 1. Create a crate

```shell
cargo new rsmack-demo
cd rsmack-demo
```

## 2. Add the dependency

One dependency brings every macro:

<Tabs>
	<TabItem label="cargo add">
		```shell
		cargo add rsmack
		```
	</TabItem>
	<TabItem label="Cargo.toml">
		```toml
		[dependencies]
		rsmack = "1"
		```
	</TabItem>
</Tabs>

The `rsmack` facade re-exports all five macros behind its `full` feature (the default). To depend on a single macro instead, add `rsmack` with one feature — for example `cargo add rsmack --no-default-features --features edoc` — or depend on the standalone crate, such as `rsmack-edoc`.

## 3. Create a constants file

`edoc` reads constants from a real file inside your crate's `src/` directory. Create `src/consts.rs`:

```rust
// src/consts.rs
pub const APP: &str = "myapp";
pub const MAJOR: i32 = 1;
pub const TAG: &str = concat!("v", MAJOR);
```

<Aside kind="caution" title="The constants live in a file, not an inline module">
	`edoc` resolves `from = consts` to the path `src/consts.rs` on disk and parses that file. An inline `mod consts { ... }` in another file does not satisfy the lookup. Keep the constants in their own file.
</Aside>

## 4. Document a struct from the constants

Replace `src/main.rs` with:

```rust
use rsmack::edoc;

#[edoc(from = consts)]
struct Client {
    /// Fallback docs: replaced by the edoc tuple below.
    #[edoc(("Client ", APP, " tag ", TAG, " build ", 2 * 21))]
    name: String,
}

fn main() {
    let _client = Client { name: "demo".to_string() };
}
```

Each `#[edoc((...))]` tuple evaluates its elements — string literals, constant references, and const expressions such as `2 * 21` — and turns the concatenation into a real `#[doc]` attribute on the field. The element values keep their machine types (`i128`, `f64`, `&str`, ...) until the docs are assembled.

Build once to make sure everything expands:

```shell
cargo build
```

The command returns without errors. If a constant is misspelled, the compiler reports `#[rsmack_edoc::edoc] Unresolved const ident ...` and every other broken expression on the item in the same pass.

## 5. Read the generated docs

```shell
cargo doc --no-deps --open
```

Navigate to `Client` and then to the `name` field. The rendered text reads:

```text
Client myapp tag v1 build 42
```

`APP` renders as `myapp`, `TAG` resolves the const-to-const reference to `v1`, and the expression `2 * 21` evaluates to `42`.

## 6. Wrap the fields

Add `wrap` to the same struct — or to a second struct, as here — and every field type is wrapped in the generic type you name:

```rust
use rsmack::wrap;

#[wrap(with = Option)]
struct UserDraft {
    name: String, // becomes Option<String>
    email: String, // becomes Option<Vec<String>> for Vec fields, and so on
}

fn main() {
    let draft = UserDraft {
        name: None,
        email: None,
    };
}
```

The fields are now `Option<String>`. Per-field control is available with `#[wrap(skip)]`, `#[wrap(with = "Box")]`, and `#[wrap(with = "Vec", map = "u8")]` — see the [`wrap` guide](/guides/wrap-field-types/) for the full behavior.

<Aside kind="caution" title="Order matters with serde">
	Execute `wrap` before `#[derive(Serialize, Deserialize)]`. The derive must observe the wrapped field types, not the original ones.
</Aside>
