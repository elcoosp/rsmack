Use [`seanum`](/reference/seanum/) when an enum must live in a database through [SeaORM](https://www.sea-ql.org/SeaORM/). The macro generates the `DeriveActiveEnum` plumbing with deliberately minimal default derives and adds integer discriminants or a migration helper on demand.

## Define a string-backed enum

```rust
use rsmack_seanum::seanum;

#[seanum(
    rs_type = "String",
    db_type = "String(sea_orm::sea_query::StringLen::None)",
    rename_all = "snake_case",
    derives("::serde::Serialize", "::serde::Deserialize")
)]
#[derive(Default)]
pub enum SwitchAction {
    #[default]
    #[seanum(rename = "send_email")]
    SendEmail,
    SendSms,
}
```

The generated values are `send_email` (explicit `rename` wins over `rename_all`) and `send_sms`. The default derives are `Clone`, `Debug`, `PartialEq`, `Eq`, `Hash`, `EnumIter`, and `DeriveActiveEnum` — `serde` and `fake` support is opt-in through `derives(...)`, never a hidden dependency.

## Use integer discriminants

With an integer `rs_type` from `i8` through `u64` (plus `isize`/`usize`), the macro adds `#[repr(...)]`, a `#[sea_orm(num_value = N)]` on every variant, and a value-based `TryFrom`:

```rust
#[seanum(rs_type = "i32", db_type = "Integer")]
pub enum Level {
    Low = 10,
    Medium, // continues from 11
    High,
}
```

Explicit discriminants are honored and later variants continue from them. Duplicates are reported as a collected error and the `TryFrom` is skipped, while the enum itself still compiles.

## Generate the migration helper

`migration = true` emits a `migration_column_def()` helper for use with [`sea-orm-migration`](https://docs.rs/sea-orm-migration):

```rust
#[seanum(rs_type = "String", db_type = "Text", migration = true)]
pub enum Status {
    Active,
    Retired,
}
```

The helper maps the `db_type` to the matching `ColumnDef` method — `Text`, `Integer`, `BigInt`, `Boolean`, `DateTime`, and twelve more are covered.

<Aside kind="caution" title="Column-width db_type values have no mapping">
	A `db_type` with a type parameter, such as `"String(sea_orm::sea_query::StringLen::None)"`, has no `ColumnDef` mapping. Use `migration = true` with a bare `db_type` like `"String"`, `"Text"`, or `"Integer"`.
</Aside>

## Rename values consistently

`rename_all` accepts exactly seven cases: `snake_case`, `camelCase`, `PascalCase`, `kebab-case`, `SCREAMING_SNAKE_CASE`, `lowercase`, and `UPPERCASE`. An unknown case is a fatal error at expansion time. `enum_name = "..."` overrides the table name, which defaults to the snake-cased enum name.
