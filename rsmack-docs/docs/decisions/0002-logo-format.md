# ADR 0002: Logo format — raster source, derived assets, no upscaling

**Status:** Accepted · **Date:** 2026-11-07

## Context

The rsmack repository contains exactly **one** brand asset: `docs/logo.png` — a **512×512 RGB PNG** (135,867 bytes), referenced by the README at `width="200"`. A repository-wide search finds **no SVG and no other images** (`**/*.{svg,png,jpg,jpeg,gif,webp,ico}` → one hit). There is no vector original to trace.

The logo is a charcoal tile (`#191A1F` background, baked in, no alpha) with the wordmark "rsmack" and an orange-gradient `{ } ⚙` glyph (`#E73102` → `#FD7E09`).

Pixelation risk: the failure mode to avoid is scaling a raster beyond native resolution, or shipping an SVG without a `viewBox`.

## Decision

1. **Do not trace to SVG.** The glyph carries a two-stop gradient; a potrace-style trace would lose the gradient and produce an invented-looking logo. The skill's alternative — keep raster, use the largest rendered size as the base — is taken instead.
2. **Never upscale.** Every display size is chosen so even 3× DPR stays at or below the native source resolution:
   - Header logo (`src/assets/logo-glyph.png`, cropped glyph, 372×320) displays at 24–28 px → 3× DPR needs ≤ 84 px ✓
   - Hero logo (`src/assets/logo.png`, untouched 512×512) displays at 160 px → 3× DPR needs 480 px ≤ 512 ✓
3. **Derived assets** (generated by `scripts/brand_assets.py`, reproducible):
   - `src/assets/logo-glyph.png` — glyph-only cutout; the desaturated charcoal background is keyed to transparent with a distance-based alpha ramp (T0 = 18, T1 = 64 around `#191A1F`), crop = bounding box of saturated pixels + 6 px pad.
   - `src/assets/logo.png` — byte-identical copy of the upstream PNG for the hero.
   - `public/favicon.svg` — an SVG with a `viewBox="0 0 512 512"` wrapping the 256 px LANCZOS downscale embedded as a PNG data URI, so the Starlight favicon convention (`/favicon.svg`) is honored without quality loss.
4. **`replacesTitle` stays false:** the wordmark was cropped out of the header glyph deliberately, so the accessible text title "rsmack" renders next to the glyph.
5. Astro's experimental `svgOptimizer` is **not** enabled — there are no SVG imports in the content, and experimental flags stay off in the docs config.

## Sharpness verification

Confirmed in the Phase 7 eyeball pass from actual rendered screenshots in **both themes** (header glyph at native resolution and the hero at 160 px): crisp edges, no blur, no halo, no clipping. The glyph's transparent holes show the page background through the gear and braces as intended.
