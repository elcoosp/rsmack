# ADR 0006: Deployment URL, plugin selection, and Starlight 0.42 quirks

**Status:** Accepted · **Date:** 2026-11-07

## `site` — an assumption to revisit at deploy time

Starlight 0.42 registers `@astrojs/sitemap` unconditionally, and the sitemap integration warns (a release blocker under our zero-warning gate) without `site`. The docs are built standalone, so the deployment host is not yet known. We set:

```js
site: 'https://elcoosp.github.io/rsmack/',
```

**This is an assumption** following the GitHub Pages convention for `elcoosp/rsmack`. If the site deploys elsewhere (custom domain, different path), update `site` — and `base` for subpath deploys — and this ADR. The value does not affect local rendering, QA, or search; it only canonicalizes the sitemap and metadata URLs.

## Plugins installed

| Plugin | Version | Why |
| --- | --- | --- |
| `starlight-links-validator` | 0.27.0 | Fails the build on broken internal links — a release blocker; all in-page links are verified |
| `starlight-image-zoom` | 0.16.2 | Click-to-zoom for content images (the hero logo) |
| `starlight-heading-badges` | 0.8.0 | `:badge[...]` directives in reference-page headings mark required vs optional options |

All three declare `astro >= 7.2.10` / `@astrojs/starlight >= 0.42` peer ranges — satisfied by Astro 7.4.7 / Starlight 0.42.10.

## Plugins omitted (with reasons)

| Plugin | Reason |
| --- | --- |
| `starlight-typedoc` | Generates API references from **TypeScript** projects; rsmack is Rust. A Rust equivalent would be rustdoc-based and is out of scope for this pipeline |
| `starlight-openapi` | No OpenAPI specification exists in the repository |
| `starlight-versions` | Single released version (1.0.0); the plugin is flagged early-development, so versioned docs are premature |
| `starlight-blog` | The changelog is generated by git-cliff in the upstream repository (`CHANGELOG.md`); there is no blog content to host, and a changelog mirror would drift. Pagefind already indexes all pages, and `llms.txt` gives agents a full index |

## Starlight 0.42.10 quirks recorded for posterity

1. **`locales: { en: { label: 'English' } }` breaks sidebar slug lookups** when no `src/content/docs/en/` directory exists: `linkFromInternalSidebarLinkItem` resolves slugs with an `en/` prefix that no route carries, and every sidebar `slug:` entry throws "does not exist". Single-locale sites should set `defaultLocale: 'en'` **without** an explicit `locales` map (the UI strings are English by default anyway).
2. **The `i18n` content collection must be declared by the project** (`i18nLoader()` in `content.config.ts`) or every build warns that the collection "does not exist or is empty".
3. **Custom 404 via `src/content/docs/404.mdx` needs `draft: true`** — otherwise the catch-all route and Starlight's own `/404` page collide ("conflicts with higher priority route").
4. **`@astrojs/check` + pnpm:** the transitive `@napi-rs/wasm-runtime` peer chain resolved a **beta** `@emnapi/runtime@2.0.0-beta.2` against stable `@emnapi/core@1.11.3`, crashing on import (`bridge.setLastError is not a function`). Fixed with a pnpm override pinning `@emnapi/runtime` to `1.11.1` — the matching stable pair for the shipped WASI bindings.

## llms.txt

`llms.txt` / `llms-full.txt` are generated from the **built** routes by `scripts/generate-llms.mjs` (wired as the `postbuild` script), so they can never drift from the actual pages. Routes are recorded relative to the site root, which keeps the files correct for any deployment host.
